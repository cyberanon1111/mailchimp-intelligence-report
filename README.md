# Mailchimp Engagement Intelligence Report

Automated daily report: pulls campaign performance + link/contact-level
engagement data from Mailchimp, builds an Engagement Intelligence Report
(executive summary, campaign drill-down, who-clicked-what, repeat engagement,
behavioral segmentation), and emails a concise digest to the founders with
the full HTML/PDF report attached.

Runs on a GitHub Actions schedule — no server to maintain, no dependency on
any local machine being on.

## One-time setup

1. **Add repository secrets** — Settings → Secrets and variables → Actions → New repository secret:

   | Secret | Value |
   |---|---|
   | `MAILCHIMP_API_KEY` | Your Mailchimp API key |
   | `MAILCHIMP_SERVER` | Server prefix, e.g. `us22` |
   | `MAILCHIMP_AUDIENCE_ID` | Your audience/list ID |
   | `REPORT_RECIPIENTS` | `arjun@maps2business.com,admin@maps2business.com` |
   | `REPORT_FROM_EMAIL` | `marketing@maps2business.com` |
   | `SMTP_HOST` | Your SMTP provider's host |
   | `SMTP_PORT` | Usually `587` |
   | `SMTP_USERNAME` | SMTP login for `marketing@maps2business.com` |
   | `SMTP_PASSWORD` | SMTP password / app password |
   | `SMTP_USE_TLS` | `true` |
   | `TEST_MODE` | `true` to start — generates the report but never sends email |

2. **Test it manually** before trusting the schedule: go to the **Actions** tab →
   "Daily Mailchimp Engagement Report" → **Run workflow**. Check the run's logs
   and download the report artifact to confirm it looks right.

3. **Enable real sending**: once a manual run looks correct, edit the
   `TEST_MODE` secret to `false`. The next scheduled run (or another manual
   dispatch) will actually email the recipients.

## Schedule

Runs daily at **09:00 IST** (`30 3 * * *` UTC in the workflow file). To
change the time, edit `.github/workflows/daily-report.yml`.

## How state persists between runs

GitHub Actions runners are thrown away after each run. Two things need to
survive between days:

- `.tmp/mailchimp_reports/engagement/*.json` — per-campaign event log, used
  for incremental fetching (`since=`) and cross-campaign engagement history.
- `.tmp/mailchimp_reports/history.json` — daily aggregate snapshot log.

The workflow commits both back to the repo at the end of every run (see the
"Persist engagement state" step). Nothing else generated by a run (the HTML
report, PDF, charts, that day's JSON export) is committed — those are
uploaded as a 30-day workflow artifact instead, and are also emailed out.

## Local development

```
pip install -r requirements.txt
cp .env.template .env   # fill in real values
python3 tools/generate_mailchimp_report.py            # generate only
python3 tools/generate_mailchimp_report.py --send      # also attempt email (blocked by TEST_MODE=true)
pytest tests/
```
